## How I Approach Engineering

I care about more than getting an endpoint to return `200`.

When building or reviewing backend systems, I look at correctness under failure, concurrency behaviour, transaction boundaries, database performance, API contracts, testability, observability, and operational failure modes.

I prefer small, understandable interfaces, explicit business rules, strong automated tests, and designs that remain predictable as traffic and system complexity increase.

I also treat code review as an engineering activity rather than a style check: understand the change, challenge its assumptions, look for correctness and performance risks, verify the tests, and leave the code easier to operate and maintain.
